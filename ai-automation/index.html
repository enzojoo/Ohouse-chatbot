다섯 가지 설계 원칙

  1. 사람을 대체하지 않고 뒤를 지킨다. 지표 동기화는 기존 워크플로를 걷어내지 않고, 그것이 틀렸을 때만 조용히 고칩니다. 대체보다 보완이 실패 시 피해가 작습니다.
  2. 멱등성을 지킨다. 같은 입력이면 몇 번을 실행해도 결과가 같습니다. 값이 이미 맞으면 아무것도 쓰지 않습니다. 그래야 재실행이 두렵지 않습니다.
  3. 확정적인 일은 코드가, 판단이 필요한 일은 모델이. 조회·대조·계산은 전부 코드로 처리하고, 모델에는 이미 확정된 사실을 문장으로 옮기는 일만 맡깁니다. 모델이 숫자를 찾게 하면 창작합니다.
  4. 실패를 조용히 넘기지 않는다. 원천 데이터가 비었으면 쓰지 않고 경고만 보냅니다. 잘못된 값을 쓰는 것보다 비어 있는 편이 낫습니다.
  5. 되돌릴 수 있게 만든다. 외부에 영향을 주는 작업(등급 변경, 알림톡 발송)은 실행 대장을 남기고 롤백 도구를 함께 만듭니다.

1. 심층문의 CS 자동 분석·답변

한 줄 요약 · 고객센터가 해결하지 못해 담당자에게 이관된 문의를, 봇이 데이터를 조회해 원인을 판정하고 답변 초안까지 작성합니다.

문제

  • 고객센터에서 해결되지 않은 문의가 슬랙으로 이관되면, 담당자가 직접 여러 시스템을 뒤져 원인을 찾고 답변을 작성했습니다.
  • 이관 건의 유형은 로그인 이슈와 콘텐츠 수익화 프로그램 두 가지에 집중돼 있습니다. 두 유형 모두 "이 사람이 어떤 상태인가"를 조회하는 것이 답변의 8할입니다.
  • 조회 경로가 정산 시트·리포팅 도구·데이터 웨어하우스로 흩어져 있어, 한 건당 확인에만 상당한 시간이 들었습니다.

사람이 남는 자리

  • 초안 승인. 봇은 스스로 최종 답변을 내보내지 않습니다.
  • 전달처 판단. 어느 부서가 1차로 봐야 하는지는 조직 맥락이라 오판이 잦습니다.
  • 정책 해석이 필요한 건. 규정이 확정되지 않은 사안은 임의 답변을 금지하고 있습니다.

실적과 한계

  • 8월 기준 94건을 자동 분석했습니다.
  • 로그인 유형은 초안이 거의 그대로 나가는 수준입니다.
  • 수익화 유형은 아직 재작성 비율이 높습니다. 과거 답변과 대조한 결과 완전 일치 21% · 부분 일치 18%로, 병목을 다섯 종류로 좁혀 개선 중입니다.

2. 콜·채팅 운영 지표 동기화

한 줄 요약 · 지표 적재가 조용히 틀리는 문제를, 원천을 직접 조회해 대조하고 고치는 감시 배치로 막았습니다.

문제

  • 기존 적재 워크플로는 리포팅 도구의 캐시된 마지막 결과를 가져오는 구조였습니다.
  • 원천 쿼리가 예정 시각까지 끝나지 않으면 전날 값이 오류 없이 그대로 들어옵니다. 데이터가 비어 있지도 않으니 실패 알림도 뜨지 않습니다.
  • 지표가 틀린 채로 며칠 흐르면, 그 사이의 판단이 전부 잘못된 근거 위에 서게 됩니다.

트리거와 주기

평일 09:25와 13:30, 하루 두 번 실행됩니다. 기존 적재가 끝난 뒤를 노려 배치했습니다.

설계상 주의한 점

  • 주말의 0은 정상값입니다. 토요일 인바운드가 0인 것과 데이터가 없는 것은 다릅니다. 원천 조회 결과에 해당 날짜가 아예 없을 때만 결측으로 처리합니다.
  • 적재일과 인입일을 구분합니다. 상담 시스템의 기준 날짜는 데이터가 적재된 날이지 문의가 들어온 날이 아닙니다. 과거 데이터를 다시 적재하면 특정일 수치가 폭증하는 착시가 생기므로, 집계는 항상 두 단계로 거릅니다.
  • 값이 이미 맞으면 아무것도 쓰지 않으므로, 하루에 몇 번을 돌려도 안전합니다.

실적

평일 2회 무인 실행 중입니다. 사람이 매일 조회해 시트에 옮기고 검산하던 구간이 사라졌습니다.

3. 콜봇 재인입률 자동 산출

한 줄 요약 · "콜봇이 단독 종결했다"가 "고객 문제가 해결됐다"와 다르다는 것을 증명하기 위해, 같은 고객의 재문의를 추적하는 지표를 만들었습니다.

문제

  • 콜봇 성과는 단독 종결 건수로 보고되지만, 그중 상당수는 고객이 다시 전화를 겁니다. 종결이 곧 해결은 아닙니다.
  • 재문의를 추적하려면 고객 식별자가 필요한데, 콜봇 종결 건의 연락처가 데이터 웨어하우스에 복제되지 않습니다. 일반적인 조회 경로로는 산출 자체가 불가능했습니다.

트리거와 주기

평일 09:20. 상담 시스템에서 티켓 이력을 내려받는 것부터 시트 적재까지 한 번에 수행합니다.

설계 결정 세 가지

  1. 롤링 10영업일 재계산. 새로 들어온 건만 더하면, 24시간 창이 걸쳐 있는 건의 판정이 영영 틀린 채로 남습니다. 매번 최근 구간을 다시 계산합니다.
  2. D+2 확정. 어제 건은 아직 창이 닫히지 않아 미확정입니다. 확정된 구간만 시트에 씁니다.
  3. 영업일과 공휴일을 자동 반영. 금요일 09시 인입 건의 24시간은 월요일 09시입니다. 공휴일은 라이브러리와 과거 데이터 학습으로 자동 판별합니다.

실적

  • 8월 콜봇 단독 종결 1,640건 중 영업일 24시간 내 재인입 604건(36.8%), 상담 유형까지 같은 재인입 211건(12.9%).
  • 같은 방식으로 상담사 처리분도 산출해 비교 기준선을 만들었습니다. 콜봇 품질 논의가 인상이 아니라 수치 위에서 이뤄지게 됐습니다.

4. VIP 등급 고정·해제

한 줄 요약 · 계약 고객 등급 부여와 기간 만료 원복, 안내 발송까지 전 구간을 무인화했습니다. 외부에 직접 영향을 주는 작업이라 안전장치를 가장 두껍게 넣었습니다.

문제

  • 시공 계약 고객에게 VIP 등급을 부여하고 기간이 지나면 되돌리는 업무입니다. 대상 산출, 등급 변경, 원복, 고객 안내가 모두 수기였습니다.
  • 대상이 매주 쌓이는 구조라 처리가 밀리면 적체가 누적됩니다. 가동 시점에 이미 662건이 밀려 있었습니다.

트리거와 주기

평일 09시~18시 안에서만 실행됩니다. 업무 시간 밖 실행을 막아둔 이유는, 예약 실행이 밀렸다 한꺼번에 따라잡는 동작이 주말 오발송으로 이어질 수 있기 때문입니다.

안전장치

  • 발송 상한과 연속 실패 상한. 한 번에 나갈 수 있는 알림톡 수를 제한하고, 연속 실패가 임계치를 넘으면 즉시 멈춥니다.
  • 중복 발송 차단. 발송 기록을 즉시 남겨 같은 대상에게 두 번 나가지 않게 합니다.
  • 보호 가드. 특정 조건의 회원은 자동 처리에서 제외하고 사람이 판단하도록 남깁니다.
  • 전수 감사와 롤백 도구. 가동 직후 7,284행을 원본과 1:1 대조해 96건을 조치했습니다. 잘못 처리된 건을 되돌리는 도구를 함께 만들어 두었습니다.
  • 감시 배치. 별도 배치가 주기적으로 실행 상태를 점검하고, 예정된 실행이 누락되면 알립니다.

실적

  • 가동과 함께 적체 662건 해소, 전수 감사로 기존 오류 96건 정정.
  • 알림톡 연동 후 첫 실발송에서 해제 예고 188건 · 적용 안내 6건 · 등급 원복 158건을 처리했고, 소요 시간은 약 1.6분이었습니다.
이 자동화는 다른 파트의 업무를 대신 자동화한 사례입니다. 절감된 시간은 해당 파트에 귀속되며, 서비스운영팀의 성과는 "도구를 만들어 이관한 것"까지입니다.

5. UID 변경 처리

처음에는 어드민에 API가 없다고 보고 브라우저 자동화(RPA)로 만들었습니다. 화면이 개편될 때마다 전부 다시 짜야 했고, 실제로 한 차례 통째로 복구해야 했습니다. 이후 API가 존재한다는 것을 확인하고 API 직접 호출로 전환하면서 화면 변경에 영향받지 않는 구조가 됐습니다. 같은 패턴을 VIP 등급 자동화에 그대로 재사용했습니다.

문제

상담사가 처리한 건 중 유관 부서가 알아야 하는 건을, 사람이 골라 슬랙에 옮겨 적었습니다. 누가 담당인지 매번 확인해야 했고, 옮기는 과정에서 누락이 생겼습니다.

  • 간헐적 누락 결함 수정. 함수가 두 경로로 중복 실행되면서 한쪽이 잠금을 먼저 가져가고 조용히 종료되는 문제가 있었습니다. 실행 권한을 확인해 방어하도록 고쳤습니다.
